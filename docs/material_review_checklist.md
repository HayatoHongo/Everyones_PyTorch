## 教材レビュー項目

**教材作成者自身が、教えてる内容を少なくとも1ヶ月以上以前に学習済みであり、技術的な正誤を判断する能力があること。**

## ツール

基本的にコーディングエージェントを使う。Colab Pro の Colab AIエージェントでもいいし、VS codeのCodexやClaudeでも良い。
VS codeはエージェントで編集した後は、編集内容がnotebookに見えてこないことが多くある。
この場合、必ずCtrl+Sで上書き保存をする。「overwrite と revert」が出てくるが、これはrevertを選ぶ。
エージェント編集から手書き編集に移行する際も、必ず上書き保存をする。
上書き保存をせずに手書きで編集すると、競合関係が発生してどちらかの編集内容を捨てる必要が出てくる。

## 認識してほしいこと

教材作成はこだわろうと思えば、いくらでも時間を投下できる。
ただ、そもそも教材作成よりも、あなた自身の勉強に時間の方が大事。
そのため、教材作成は「90点くらいの品質でなるべく早く」作るものである。
「どれだけ時間をかけてもいいから100点の品質を目指す」ものではない。

自分自身が受講者の気持ちになって、上から読み進めていく。

3回以上同じ手直しをするなら、それはstep1~step8で使用した、作成手順に不足がある。
作成手順のプロンプトに新たにstep(step9以降)を追加して、手直しに用いたプロンプトを登録する。
こうすることで、元々の作成手順そのものをブラッシュアップして、ノウハウのストック化を行う。

とにかく、以下の項目を意識して、実際にnotebookを順に実行しながら、受講者がつまづく点をなくしていく。

### 修正時に意識すること（優先順)

なお、notebookの雛形はAIエージェントによる自動生成である。
そのため、以下の項目だけでは網羅できないこともある。
つまりここに書かれていないことでも、必要だと判断したら迷わず修正を行うこと。

### A.1 知的好奇心を刺激する余談を1つ加える

つまらなかったら意味がないので、知的好奇心を刺激する余談を1つ加える。
これは、わかりやすいとか、比喩が面白いとか、ということとは違う。
知的好奇心をくすぐるポイントを1つ加える。
なお余談なので、極端に長いことは避ける。理想的には1分で出来る内容、最長でも5分くらいで理解できる内容。
メイントピック自体に関して、あるいはメイントピックの発展にする。
適切な余談が1分以内に思いつかない場合は、余談なしで進めてOK。

### A.2 行列(テンソル)の要素レベルの計算が理解できるようになっているか？

数式も、コードも、裏にある実態の計算は行列の各要素の計算である。
あらゆるnotebookの究極の1つの目的は、この裏にある行列の計算を、要素レベルで理解することに尽きる。
数式も、コードも、あくまでそれらの要素レベルの計算に対する抽象化した表現である。

数式やコードを見たときに、自然と裏の行列計算が要素レベルで見えてくる状態へと、読者を進化させること。
これが絶対目標である。
「コードや数式が表面的に出てるだけで、行列計算が理解しづらい」部分を1つ残らず修正する。
print文による要素の表示を増やす。行列を要素レベルで表示した数式を増やす。

- print_formatted_tensorは以下で使用できる
```python
!pip install git+https://github.com/HayatoHongo/print_formatted_tensor.git
from torch_print_tensor import print_formatted_tensor
```

### A.3 新しい概念ではなく、既存の概念の発展として紹介する

新しい概念としてではなく、既存の概念の発展として紹介する

これは最も賢い紹介の仕方である。例えば、MNISTの画像認識の際に、「49 -> 25 -> 10」のニューラルネットワークのモデルを構築するとする。
その際、「49 -> 10」の線形変換モデルを復習して、そこに25の隠れ層を導入する、という流れにする。
これなら、新しいモデルを理解するという認識ではなく、既存のモデルが改良された、という認識になる。
つまり読者は1から何かを理解するのではなく、今まで学んだ内容との差分だけを勉強すればいい、ということになり、劇的に理解の負担が軽くなる。

### A.4 トピックと関係のない「枝分かれ」を消す

大前提として、1つのnotebookは1つの要素技術に対するメッセージしか持たない。1ファイル1トピックである。
前述の通り、目的は裏にある行列の計算を、要素レベルで理解することに尽きる。
そのため、1つのnotebbokの中で、余計なメッセージやトピックが発生していないかをチェックする。
それらの分岐を発見したら直ちに削除、または補足として大幅に圧縮する。

### A.5 コードセルは「1処理＋表示」を基本とする

基本形は、処理を1行で実行し、その結果を次の行で表示する形式とする。

```python
Y_pred = X @ W
print_formatted_tensor("Y_pred", Y_pred)
```

ただし、以下の場合は例外とする。なお、この例外は非常によくある。
* 複数の処理をまとめた方が、処理の意味を理解しやすい場合
* 一連の処理をまとめて確認するまとめセル

### A.6 技術的な正しさ

この作業は作業の終盤に行う。
Notebook全体を強力なコーディングエージェントに読み込ませ、致命的な技術的な誤りや見落としがないか確認する。
プロンプト「Notebook全体について、致命的な技術的な誤りや見落としがないか確認してください。必要に応じて修正すること。些細なものはスルーして良い。」

難しい概念についても、比喩による曖昧な説明に頼らない。
代わりに、数値の小さいシンプルな疑似データを使い、実際の計算やコードを通して説明する。
