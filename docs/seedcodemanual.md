# シードコード作成マニュアル

## 1. シードコードとは

シードコードとは、コーディング教材を作成する際の土台となるコードである。

教材では、学習者がコードを段階的に書き足しながら、最終的な実装に到達する。そのため、シードコードを作成する際には、最初に次の二つを定める。

* **スタート地点のコード**
* **終了地点のコード**

スタート地点から終了地点に向かって、必要な概念や実装を少しずつ追加していくことで、教材全体を構成する。

**シードコードを作れる人の条件**

シードコードは、対象技術を深く理解している担当者が作成する。

少なくとも、担当者は次の条件を満たしている必要がある。

1. 対象となる実装を、自分で最後まで動かした経験がある。
2. 再現実験や類似実装を行った経験がある。
3. 各コードが何のために存在するのか説明できる。
4. コードを変更した場合に、結果がどのように変化するか予測できる。
5. どの実装が本質で、どの実装が補助的なものか判断できる。
6. 複雑な実装を、学習用の最小構成に落とし込める。

---

## 2. 最初に終了地点を決める

シードコード作成では、最初に**終了地点のコード**を作成する。

スタート地点のコードは、教材によっては存在しなくてもよい。
一方で、終了地点のコードは、原則として必ず必要である。

終了地点のコードは、教材を最後まで進めた学習者が完成させるコードであり、教材全体の学習目標を具体的に表している。

例えば、大規模言語モデルを扱う教材であれば、終了地点は、可能な限り簡略化された言語モデルの学習・推論コードになる。

終了地点が曖昧なまま教材を作り始めてはいけない。終了地点が定まっていなければ、途中で何を説明するべきか、どの実装を残すべきか、教材を何章に分けるべきかを判断できないためである。

---

## 3. 終了地点のコードは限界まで単純化する

終了地点のコードは、単に動けばよいわけではない。

教材の目的を達成できる範囲で、可能な限り単純でなければならない。

不要な機能、例外処理、抽象化、クラス分割、設定項目、外部ライブラリへの依存などは、できるだけ取り除く。

LLMを用いて、以下のプロンプトを5回繰り返して、簡素化する。

> 世界で一番わかりやすく初心者に優しい教材でありたい。 一般論に縛られすぎており、実は省略できる機能や要件があることに気づいていない。 あなたはthink out of the boxで、実は省略できる機能や要件について指摘する。

終了地点のコードが複雑であるほど、そこに到達するまでに説明しなければならない概念が増える。その結果、教材が長くなり、学習者の負担も大きくなる。

したがって、終了地点のコードをどこまで小さくできるかが、教材全体の工数を大きく左右する。1つのモジュールを消すだけで、1つのchapterを削除できる。極めてレバレッジが大きい。単純化に対しては10時間以上投資する。最終的に、投資した時間より確実に多くの時間を削減できる。

---

## 4. 終了地点のコードを実際に動かす

終了地点のコードは、必ず担当者自身が最初から最後まで実行する。

次の点を確認する。

* 実行環境を新しく作った状態でも動くか
* 必要なライブラリやデータが明確か
* 上から順番に実行すれば最後まで到達できるか
* 実行結果が毎回大きく変化しないか
* 不要なセルやコードが残っていないか
* 学習者が理解する必要のない処理が含まれていないか
* コメントや変数名が、実際の処理内容と一致しているか

## 5. スタート地点を決める

必要な概念を洗い出した後、教材のスタート地点を決める。

スタート地点は、学習者の想定知識によって変わる。

例えば、学習者がPythonの基礎を理解している場合は、データの読み込みから始められる。一方、変数や関数に慣れていない場合は、より小さなコードから始める必要がある。

スタート地点のコードは、必ずしも必要ではない。

最初の章でゼロからコードを書き始める教材であれば、空のノートブックや、ライブラリのインポートだけをスタート地点としてもよい。

## 13. 分割と完成条件

シードコードは、次の条件をすべて満たしたときに完成とする。

* 各章のシードコードについて、要素技術を理解するための、実装上の細かい知識を列挙する。
例えば、クロスエントロピーなら、softmax, 情報量、KLダイバージェンス, エントロピー、クロスエントロピー, 確率分布
これで、もしも細かい知識が5つ以上必要なら、それは分割が足りない。
その章を2つ（前後）に分割する。この時も、以下の原則を守る

```
Chapter{i}のシードコードは、Chapter{i-1}のシードコードとの差分を示す。
以下の規則に従って直前の章との差分を示す。
なお、差分は直前の章との差分のみに留めて、2つ以上前の章の差分は逆に表示しない。

注意点として # 変数名は既存のままにする。勝手に変えないこと。 
# 新しく追加した部分は ########## NEW ########## で囲む 
# 不要になった部分は """DELETE\n code \n""" で囲む 例：
 """ DELETE code self.train_read_position = 0 """
```

全ての章について、細かい知識が4以下になるまで、分割を繰り返す。
それを持って完成とする。

## 14. 最も重要な原則

シードコード作成で最も重要なのは、最終的なコードを先に作り、そのコードを限界まで単純化することである。

教材の長さ、章数、説明する概念、練習問題の内容は、すべて終了地点のコードから逆算して決める。

複雑な完成コードを、そのまま細かく分割して教材にするのではない。

まず完成コードから不要なものを削り、学ぶべき本質だけを残す。そのうえで、学習者が一段ずつ理解できる順番に、実装を組み立て直す。

> 終了地点のコードの品質が、教材全体の品質の上限を決める。
